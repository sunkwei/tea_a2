LLM Agent 任务排队接口需求说明书

文档版本：v0.1
文档状态：需求草案
适用范围：LLM Agent 任务提交、排队调度、交互挂起、状态查询与结果导出接口服务
说明：本文中的接口路径、字段为需求草案，最终以实现时的 OpenAPI 定义为准。
1. 背景与目标

当前 LLM Agent 执行任务时，通常一次只能处理一个任务。业务侧需要一次性提交多个任务，并希望：

    多个任务进入队列，按规则串行执行；

    同一队列同一时刻最多只有一个任务处于运行态；

    任务执行过程中如需用户交互，则当前任务挂起，不阻塞后续任务执行；

    任务保留完整状态，包括输入、上下文、消息、工具调用、交互记录、检查点、生成物和最终回答；

    提供任务状态接口，可查询历史任务的排队情况、执行状态和完成情况；

    支持导出任务结果，包括最终回答、生成物、事件记录等。

本需求说明书用于指导该排队接口的服务端需求、接口定义、状态机、数据模型和验收标准。
2. 范围
2.1 包含范围

    任务提交接口；

    任务队列与串行调度规则；

    任务全状态持久化；

    交互请求挂起与恢复；

    任务状态、历史列表、事件查询；

    任务结果与生成物导出；

    任务取消、重试等控制能力；

    幂等、权限、审计、可观测性等非功能需求。

2.2 不包含范围

    LLM Agent 内部推理算法和 Prompt 设计；

    前端交互页面；

    具体 LLM 供应商接入实现；

    复杂工作流编排和多 Agent 协作；

    默认不包含任务抢占执行。交互恢复后的任务重新排队，不抢占当前运行任务。

3. 术语
术语	说明
Agent	执行 LLM 任务的智能体实例或配置
Task	一次提交给 Agent 的完整任务
Queue	任务排队队列，默认同一 Agent 或同一租户下串行
RUNNING	正在执行的任务，同一队列最多 1 个
WAITING_INPUT	任务需要用户/外部交互，已挂起，不占用执行槽
全状态	任务元数据、消息、工具调用、交互、检查点、生成物、错误、事件等
生成物	任务产生的文件、表格、图片、代码、文档等
事件	任务状态变化、步骤执行、交互请求等增量记录
导出	将任务最终回答、生成物、事件和状态打包下载
4. 角色与使用场景
角色	主要操作
任务提交方	提交任务、查询状态、回复交互、取消任务、导出结果
Agent 执行器	拉取可运行任务、更新状态、写入检查点、请求交互、提交结果
运维/审计人员	查询队列和历史、排查失败、审计任务
管理后台	展示队列长度、运行任务、等待交互任务、失败任务

典型场景：

    用户连续提交任务 A、B、C，A 运行，B、C 排队；

    A 执行中需要补充信息，A 变为 WAITING_INPUT，调度器启动 B；

    用户回复 A，A 重新进入队列；B 继续运行，不被打断；

    B 完成后，A 恢复运行；

    用户通过历史接口查询 A、B、C 的状态，并导出 A 的最终回答和生成物。

5. 总体业务规则

    串行执行：同一队列同一时刻最多一个 RUNNING 任务；默认队列粒度为 Agent 实例，可配置为全局或租户级。

    挂起不占槽：WAITING_INPUT 任务不占用执行槽，调度器继续选择下一个 QUEUED 任务。

    恢复不抢占：交互回复后任务进入 QUEUED，待当前 RUNNING 任务结束后按队列规则恢复，不抢占。

    全状态持久化：任务每次状态变更、交互、工具调用、检查点和生成物均需持久化，服务重启后不丢失。

    历史可查：任务完成后仍可查询状态、事件、最终回答和生成物元数据。

    导出可追溯：导出内容需包含任务状态、最终回答、生成物清单和关键事件。

    幂等提交：提交接口支持幂等键，重复提交不产生重复任务。

    租户隔离：不同租户任务、生成物和事件不可越权访问。

7. 任务状态机
7.1 状态定义
状态	说明	是否终态
QUEUED	已入队，等待调度	否
RUNNING	正在执行，同一队列最多一个	否
WAITING_INPUT	等待用户/外部交互，不占执行槽	否
COMPLETED	成功完成	是
FAILED	执行失败且不可自动恢复	是
CANCELED	被用户或系统取消	是
7.2 允许的状态转换
text

提交成功              -> QUEUED
QUEUED               -> RUNNING         调度器选中
RUNNING              -> WAITING_INPUT   需要交互
WAITING_INPUT        -> QUEUED          用户回复后重新入队
RUNNING              -> COMPLETED       执行成功
RUNNING              -> FAILED          不可恢复错误
RUNNING              -> QUEUED          服务重启后从检查点恢复（系统转换）
QUEUED               -> CANCELED        排队中取消
WAITING_INPUT        -> CANCELED        挂起中取消
RUNNING              -> CANCELED        运行中协作取消
FAILED               -> QUEUED          重试，attempt + 1

规则：

    COMPLETED、FAILED、CANCELED 为终态，默认不可再次运行；

    重试需新增 attempt，历史 attempt 事件保留；

    交互回复只允许对当前有效 interaction_id 操作；

    同一任务同一时刻最多一个未完成交互请求。

8. 接口需求
8.1 通用约定

    协议：HTTPS + JSON；

    鉴权：Authorization: Bearer <token>；

    租户：通过 token 或 X-Tenant-Id 识别，服务端做隔离；

    统一响应：

json

{
  "code": 0,
  "message": "ok",
  "request_id": "req_xxx",
  "data": {}
}

    分页：page_size + cursor 或 page + page_size；

    幂等：提交和交互回复支持 Idempotency-Key；

    时间：ISO 8601 UTC。

8.3 关键接口字段
提交任务 POST /v1/agent-tasks

请求关键字段：
字段	类型	必填	说明

input	object/string	是	任务输入

请求：interaction_id、response、idempotency_key。

10. 非功能需求
类别	需求
可靠性	任务状态和事件持久化，服务重启不丢失；运行中任务可从最近检查点恢复或明确标记失败
一致性	状态变更与事件写入需任务级一致；调度器需避免同一任务重复运行
幂等性	提交、交互回复、取消、重试支持幂等
并发安全	并发提交、回复和调度不产生重复入队或双运行
性能	提交 P95 ≤ 300ms；状态查询 P95 ≤ 200ms；调度延迟通常 ≤ 1s；导出大文件可异步
安全	鉴权、租户隔离、生成物下载有效期、敏感字段脱敏、禁止在日志记录密钥
可观测	队列长度、运行数、等待交互数、任务时延、失败率、导出成功率指标
审计	提交、回复、取消、重试、导出、下载均记录审计日志
保留策略	任务和生成物保留期限可配置，过期清理需审计
限流	提交和查询接口支持租户级限流，返回 429
11. 异常与边界
场景	期望行为
重复提交相同幂等键	返回原任务，不重复入队
任务不存在或越权	返回 404 或 403，不泄露其他租户信息
回复非等待交互任务	返回 409 Conflict
重复回复同一交互	幂等成功或返回已处理，不重复入队
取消终态任务	返回 409
运行中取消	标记取消请求，执行器协作停止后置 CANCELED
生成物超大	导出异步化或返回部分导出说明
服务重启	QUEUED 继续排队；RUNNING 根据检查点恢复为 QUEUED 或按配置置 FAILED，需保留全状态
交互超时	按配置置 FAILED、CANCELED 或继续等待，P1
12. 验收标准

    串行执行：提交 A、B、C 三个任务后，同一队列同一时刻仅一个 RUNNING，其余为 QUEUED。

    交互挂起：A 需要交互时变为 WAITING_INPUT，调度器随后启动 B，A 不占用执行槽。

    恢复不抢占：回复 A 后 A 变为 QUEUED；B 继续运行；B 完成后 A 才恢复运行。

    历史查询：可按状态、Agent、时间范围查询历史任务，返回排队位置、完成状态和分页信息。

    状态详情：查询任务返回当前状态、进度、待交互信息、生成物摘要和错误摘要。

    结果导出：完成任务的 ZIP 导出包含 manifest.json、最终回答、生成物、交互记录和关键事件。

    生成物下载：生成物可单独下载，越权访问被拒绝，过期链接失效。

    幂等提交：相同幂等键重复提交只产生一个任务。

    并发安全：并发提交 100 个任务，不出现重复运行或任务丢失。

    重启恢复：服务重启后任务状态不丢失，排队任务继续调度，运行中任务可按检查点恢复或明确失败并保留状态。

    取消与重试：排队、挂起、运行中任务可取消；失败任务可重试且历史 attempt 保留。

    审计与可观测：关键操作有审计日志，队列和任务指标可查询。

13. 假设与待确认问题

    串行粒度是全局、按 Agent、按租户还是按自定义队列？默认建议按 Agent 队列。

    交互回复后任务排到队尾，还是保留原优先级或插入队首？默认队尾。

    是否需要任务优先级和抢占？当前默认不抢占。

    运行中服务重启后，是自动从检查点恢复，还是标记失败等待人工重试？

    导出大文件阈值和异步导出策略。

    任务、事件和生成物保留期限及清理策略。

    是否需要 Webhook 状态回调？如需，回调失败重试策略待定。

    权限模型是租户级、项目级还是任务级？

    生成物大小、类型和数量限制。

    是否需要多 Agent 并行队列？当前需求为串行执行。
