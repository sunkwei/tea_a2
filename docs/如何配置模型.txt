如何配置模型
============

a2 要连一个模型服务才能干活。配置写在这个文件里：

    ~/.tea_agent/provider.yaml

包里有一份模板 provider.yaml.sample。复制过去，改两处，重启 a2：

    cp provider.yaml.sample ~/.tea_agent/provider.yaml
    vi  ~/.tea_agent/provider.yaml

要改的就两处：

    api_url    模型服务的地址
    api_key    你的 key

最小的一份（够用了）：

    providers:
      deepseek:
        api_url: https://api.deepseek.com
        api_key: sk-你的key
        models:
          deepseek-chat: {}

不用管别的：providers 里第一个 provider 的第一个模型，就是 a2 默认用的。

改完重启 a2，然后看它认了没有：

    curl -s http://127.0.0.1:8383/api/config/status

里面会写现在用的是哪个 provider、哪个模型。
也可以打开 http://127.0.0.1:8383/ → 设置 → 模型，那里能看也能改。

常见的地址
----------

DeepSeek
    api_url: https://api.deepseek.com
    api_key: sk-…      在 https://platform.deepseek.com/api_keys 拿
    models: deepseek-chat: {}

MiniMax
    api_url: https://api.minimax.cn/v1
    api_key: sk-…
    models: MiniMax-M3.1-Flash: {}

自己的网关、vLLM、硅基流动这类 OpenAI 兼容的
    api_url: https://你的地址/v1
    api_key: sk-…
    models: 你的模型名: {}

    api_url 带不带 /v1 都行：带了补 /chat/completions，不带补 /v1/chat/completions。

注意
----
key 写错或地址不通，a2 会在日志里写明原因：

    tail -f ~/.tea_agent/logs/tea_agent.log        # 直接跑的
    journalctl -u a2 -f                            # 用 systemd 跑的

key 里有 # : " 这些字符，用引号包起来。

模型名要和对方给的完全一样，大小写也算。写错会收到 model not found。

这个文件只管模型。别的设置不在这里，在：

    ~/.tea_agent/tea_agent.yaml                  机器级
    <工作区>/.tea_agent_run/settings.yaml       按工作区，优先级更高

    （一轮最多用几次工具、最多花多少 token、能不能碰工作区外面的目录，都在那边）

换 key 不用重装，改完文件重启 a2 就行。

文件里存着 key，权限收一下：

    chmod 600 ~/.tea_agent/provider.yaml

字段的完整说明在 docs/config.md，命令清单在 docs/tea_a2_manual.md。
